On 11.11.26 the Model and training session listed four questions it wanted to send to Prof. Nierhoff and asked Emranul
whether meeting 2 (9.11.26) had answered them. Emranul answered in the chat, in his own words:

1. Own tracks for training: "we can use our own track to teach it" (question 15 in `05_meetings/requests_to_professor.md`).
2. What an unseen exam track can contain (dashes, loops, hairpins): "It can be anything".
3. How a run is judged: "first we need to properly do the task, then how fast are we doing, there are 5 other team
   whoever performs best get the better grades".
4. Recording corrections where the model goes wrong: "ya we can train in specific things the model lacks".

Asked the same evening whether these four answers are the professor's own words, Emranul said yes. No note of meeting 2
exists in the project, and `05_meetings/requests_to_professor.md` (the orchestrator's file) still lists question 15 as
open: the orchestrator or Emranul should enter the four answers there, with the date he got them.

The session then asked four more questions, each with the choice "he has not said"; Emranul chose (11.11.26):

5. The robot must stop by itself when the puck reaches the end of the line.
6. The team decides how the unseen sheet lies on the table and where the robot starts.
7. One try per track.
8. The unseen tracks are seen only at the exam (no look and no practice before the graded run).

**Why:** these answers decide the plan after the first robot test ([[project-first-robot-test]]): whether new printed
tracks may be recorded, whether dashes and loops must work on a line never seen, whether correction rounds are allowed,
how much the stop counts and how much work "any orientation" needs for the exam.

**How to apply:** plan for dashed lines, loops, crossings and hairpins on unseen tracks as certain, not as a risk; record
demonstrations on new printed tracks; correction rounds and targeted recoveries may be used; finishing properly comes
first, speed second, and the result is ranked against five other teams, so time is worth tuning once finishing works.
The stop is part of finishing and there is one try: a run that never stops or stops early fails, so the stop on unseen
lines (offline: right place in 106 of 209 episodes, never in 71, early in 32) ranks beside following the line, and
reliability over many runs counts more than the best run. Since the team lays the sheet, a written lay-out and start
rule (which end to start from, the line leaving straight away, everything within reach) can remove most of the
orientation risk at the exam; Emranul's wish for any orientation stays a quality aim. The rule must be practised on
tracks nobody has seen, against the clock.
Still not known: how close to the line's end the puck must be, a time limit, whether the driver may scale the model's
step, whether the model may see the previous picture, the table and the light.

Emranul's own priority (11.11.26): "speed matters, I think we should focus more now on finishing the task, once its done
learning we can make it better to be faster". So no effort goes into speed until the robot finishes reliably; the
seconds of every run are logged from now on so that the later speed work starts from numbers.

On orientation (11.11.26, late): Emranul asked why a robust model should not finish in any orientation. After the
answer (the arm's reach and the forearm camera set limits no model removes; the rest needs recordings in other
lay-outs, each done the same way) he said "lets stick with the initial planning for now". So the plan stays as
written: a lay-out rule for the exam (to be decided with Marshal), one first look at an unrecorded lay-out in test
sitting C, about a quarter of the new recordings in other lay-outs, and no extra hours for "any orientation" until
he asks for them again.
